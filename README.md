# devcontainer-features

Dev container Features shared across my projects, published to
`ghcr.io/ntodd/devcontainer-features/<feature>`.

| Feature | |
|---|---|
| [orca](src/orca) | The container's own headless Orca runtime, installed and updated on every start |

## Using one

```jsonc
"features": {
  "ghcr.io/ntodd/devcontainer-features/orca:1": {}
}
```

## Layout

The layout follows [devcontainers/feature-starter](https://github.com/devcontainers/feature-starter).

- `src/<feature>/`: `devcontainer-feature.json`, `install.sh` (runs as root at
  image build), any scripts it installs, and `NOTES.md`, which the release
  workflow merges into the generated `README.md`
- `test/<feature>/`: `test.sh` for the default options, `scenarios.json` and
  one script per scenario, run by `devcontainer features test`
- `scripts/`: checks `features test` can't express

## Testing

CI runs everything below with the devcontainer CLI version Foreman pins
(0.89.0), so features are built the way Foreman environments build them.
Locally, on a Linux box with Docker:

```bash
CLI="npx --yes @devcontainers/cli@0.89.0"

# orca: installer unit tests, offline, a few seconds (needs python3, openssl)
bash test/orca/unit/test-orca-install.sh

# Default options against Debian and Ubuntu. These download Orca and run it.
$CLI features test -f orca --skip-scenarios -i mcr.microsoft.com/devcontainers/base:debian .
$CLI features test -f orca --skip-scenarios -i mcr.microsoft.com/devcontainers/base:ubuntu .

# Scenarios (pinned version, port, pairing address)
$CLI features test -f orca --skip-autogenerated .

# A compose-based devcontainer: init and postStartCommand reach the service
scripts/test-compose.sh
```

## Releasing

1. Bump `version` in the feature's `devcontainer-feature.json` (semver; consumers
   pin the major, `:1`).
2. Merge to `main`, then run the **Release dev container features & Generate
   Documentation** workflow by hand. It publishes to GHCR and opens a PR with
   the regenerated feature READMEs.
3. The first publish creates the GHCR package as **private**. Make it public
   (package settings → Change visibility) so Foreman boxes and other builds can
   pull it without registry credentials.

Regenerate a feature README locally with
`$CLI features generate-docs -p src -n ntodd/devcontainer-features --github-owner ntodd --github-repo devcontainer-features`.
